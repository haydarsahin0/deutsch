# Growth analyst

Files: `docs/growth/LOG.md` (append-only table: date, video, views, subs, notes) and one analysis file per check-in `docs/growth/YYYY-MM-DD.md`. Spawn ONE Opus agent (strategy matters) with the screenshot path(s) and the numbers the owner typed; it Reads each image once, appends to LOG.md, writes the analysis, and returns a ≤ 25-line Turkish summary you forward.

## What the analysis must contain
1. What the numbers mean for the channel's stage (Shorts test batches; long videos grow slowly via search; sub conversion % vs. typical 0.1–1 % for Shorts) — honest about small samples.
2. Prioritised actions for the next days that fit the pipeline and the tight AI budget. Evergreen ones: set **Related video** on every Short (only clickable Short→long link — links in Shorts descriptions/comments aren't clickable); pinned comment as Melo (German); reply to comments within 24 h with a question; first 1–2 s of each Short = wrong sentence + reaction; end screens + playlists; Test & Compare thumbnails; Community-tab polls (German); consistent 17:05 CET slot.
3. 2–3 next long-video topics with search demand, each yielding 3 Shorts.
4. **Monetization projection** when asked: YPP = 1,000 subs + 4,000 public long-form watch hours in 12 months (Shorts views don't count) or 10 M Shorts views in 90 days; lower tier 500 subs + 3,000 h or 3 M Shorts views (verify in Studio „Verdienen“). Hours = views × avg view duration; give pessimistic/realistic/optimistic dates from the observed trend.
5. Next check-in date and exactly which screenshots to send (Short: overview, viewed-vs-swiped %, retention; long: impressions, CTR, traffic sources, avg view duration, retention; weekly: countries/age).
